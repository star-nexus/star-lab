# 分析

R3c 的缺口在输入的写入边界：旧输入直接调用Python System，而Rust已经持有另一个权威世界。
把原Python系统保留在展示World中会造成两套状态；把人工动作伪装成Agent请求又会引入注册、认领、统计和不同的动作语义。
因此本轮采用独立可信本地命令接口，UI仍做选择/命中/相机，Rust复用已验证的规则执行。

差分明确验证了历史差异而没有统一它们。UI Wait/Garrison与Agent Rest不同；工具栏/键盘结束回合不同；
实时本地筑垒与handler前置资源校验也不同。114项新增契约包含边界拒绝、缺失系统、跨世界生命周期，防止迁移顺便改变这些规则。

仅检查展示epoch还不够：旧控制器可能先修改新世界，再在绘制时发现不匹配。
现在epoch在native同一锁内、写入和增量提取之前检查。失败命令也不能消费新世界的首批展示；4个专门契约验证无状态变化且完整首批仍可提取。

复杂度方面，接口只传命令，返回时消费已有变化队列；不逐Unit跨语言写组件，不重建UI实体。
没有在本轮声称总体O(active)、CPU加速或性能容量；原输入选择遍历、Python面板/绘制成本、Rust现有串行内核都尚在。
Cocoa四场景的48个合成SDL事件通过实际分发器，证明输入写入路径连通。工具栏另外直接调用低层方法，不能把它写成物理鼠标完整GUI验收。

确认边界：GameScene/后端入口还未挂接，完整HUD数据与post-game传输/结算尚缺；本地命令差分显式关闭LLMSystem.update。
R3c的3Unit画面与本轮3Unit交互均不能替代5000/1000长期容量验收。
