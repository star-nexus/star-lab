# 分析

## Observation

所有原始窗口run及完整门槛见comparison.json，单次请求与逐帧样本保留在raw。旧5000-Agent8ms预算帧P99为26.354ms、世界30Hz，但观测响应P99为26.594秒，完成比例0.550；因此FPS不能代表Agent交互实时性。18ms预算观测P99仍3.461秒，帧39.710ms且Hz28.517，单纯加预算不能解决本配置。

## Hypothesis / instrumentation

假设主要开销来自Rust世界step、Unit面板并行不足或响应装配。原窗口已有world/delta/apply/display及观测build/encode/decode分段。新增固定流探针把build拆成Rust+绑定与Python服务端decode，同时保留每条实际动作、墙钟、tick及展示事件。探针在测量区间外验证完整响应hash及最终状态，计时不等于窗口端到端计时。

## Evidence / root cause

旧5000-Agent8ms测试world step P99仅0.495ms。固定流传统观测平均3.223ms，服务端decode+encode共1.457ms；直接传递仍执行完整Rust查询与客户端decode，平均1.774ms。1/4线程直接传递成本接近，因为当前查询每个Agent只有1Unit，公共构建/装配和客户端转换仍串行。完整响应、事件、状态对照通过，新增正式接口也通过22契约和2217回归。

可以确认重复服务端转换是已移除的成本，不把所有剩余成本统称Python慢。真实窗口同8ms预算观测P99由26.594秒降到7.747秒，完成比例0.550→0.744；更高预算的数值见README。闭环中的动作接纳时间与实际世界轨迹随排队改变，不能拿不同实时时序的帧差值当固定工作量微测；固定流对照用于隔离计算原因。

## Remaining uncertainty / rejected claims

没有证明5000-Agent容量达标，也没有证明所有可能预算都无效。单次60秒诊断不足以推断300秒三轮或无限时长。1000-Agent/API18旧接口本次短测排队略超100ms，不能归因于R3d5转换修复，因未做旧API17的同场A/B。无新增轮询、无数据简化、无死亡减负、无丢弃慢帧。Protocol/Hub和真实LLM继续不计入。

下一步候选是让已经到达且连续的只读请求复用Rust批次中的公共观测事实；当前窗口驱动逐个请求，各自建只读上下文。必须保持接纳顺序、每Agent权限、批次统一返回时间，不能跨越写入或等待未来请求凑批。先固定流验证，再完整窗口验证；尚未实现或承诺其收益。
