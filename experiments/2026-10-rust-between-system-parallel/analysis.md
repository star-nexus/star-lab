# E4 分析

## Observation

E3 完整 9880 tick 复算，Recovery／Lifecycle／Vision 的三任务理想上界约4.0–4.3µs/tick，native占比约1.8–2.0%；单个后台 Vision 与 caller Recovery→Lifecycle 几乎保留全部预算。该上界按每个 tick 计算后平均，不能用三个独立 P99 相减。

## Hypothesis

候选读取与写入语义可分离，但调度、窄输入准备和组件发布可能耗尽较小预算。全部 System 入池、全局 Bevy Schedule 或复制全世界可能只增加成本。收益优先，因此先测一后台空任务和真实 caller 工作的预算，再决定是否拆 Vision。

## Instrumentation

`baseline/empty_fork` 都是同二进制、同线程、同私有 FFI 的实际推进。完整性能重放关闭诊断；2/4分别三轮ABBA，每轮四次完整输入。每次检查全部响应和事件hash、最终完整权威状态hash，每个step样本与seq位置保存，不丢预热或慢尾。

另做2/4各一次诊断 twin 重放；每个响应/展示/最终完整对象直接核对，诊断返回所有tick的候选条件与fork区间。独立E3的逐tick上界只对齐相同seq的候选mask。fork residual=`fork_region−recovery−lifecycle`，覆盖派发、空任务等待、catch/join及阶段计时/字典插入未覆盖部分；不是纯调度器微基准，包含额外观察开销。它支持保守筛选，不替代无诊断的完整step净收益实验。

ABBA每个seq的A=(A1+A2)/2，B=(B1+B2)/2；正的B−A表示空派发开销，不能解释为真实Vision并行收益。100-tick不重叠分块、尾80tick保留，10000次重采样seed42，区间95%。候选mask只用于同输入的分层，不按耗时删除样本；无候选的block不用于候选条件均值，但其tick保留于全量均值/分位数。

## Evidence

最终数值在 results/analysis.json；全部完整step的均值/P99/max、每轮匹配及非匹配差值、置信区间和诊断residual都保留。没有从结果中选一个最好轮次，未将P99(saving)当作完整step的P99下降。

## Root cause and rejected explanations

只有局部fork开销及匹配预算支持调度筛选时，才将其作为本方案停止原因；整段重放波动本身不能证明System之间存在净收益。空任务也可能在独立重放中表现更快，这不能证明“加一个空worker优化了游戏执行”。CPU频率、后台应用、分配/缓存、代码布局等均可能影响总耗时，本实验未对它们做因果消融，因此不为其指定已证实原因。

本轮没有实际拆分Vision，不能声称已测准备/发布、缓存迁移或完整System并行速度，也不能推断所有未来负载或所有ECS调度器无价值。
