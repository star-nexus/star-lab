# 分析：R3b 观测接口

## 1. 观察

旧 R3a 的五个已允许查询仍抛出未实现错误。两份 Python 地块列表包含相同格子却不符合已声明的坐标顺序。前后最小复现输出在 results，精确源和命令见 README。

## 2. 假设与验证方式

H1：缺少 Rust 分发/构造路径。相同规则、三 Unit 世界和注册身份直接调用本地接口即可排除网络/Hub 影响。
H2：等价内容仍会受集合遍历顺序影响。固定可见格集合，直接读两种列表，比较坐标序即可排除内容差异。

## 3. 证据与根因

R3a 五个查询均未实现；新 dispatch 与原生字段构造后成功。R0c 仅改两处集合到列表的遍历顺序，前后格子集合不变，1299 原回归通过。

后续 144 新契约覆盖 Fog 的空视野/未初始化回退、死亡/缺组件、MP/AP/混乱/移动、领地、能力选项、参数/注册/匹配子集、缓存命中和结果隔离。正式 probe 54 配置4203节点逐响应、逐世界状态、逐事件对齐，并独立重放。节点数量、动作分布与 raw SHA 见 compact。

## 4. 保留的历史行为

各观测并非同一种投影：部分旧单位查询可见死亡 Unit，阵营查询的隐藏字段和 get_faction_state 不同；单位查询 visible_area 仍为 Python set。缓存命中保留原时间和 from_cache，失败写动作也改变查询版本；有效缓存随世界快照导入。

普通非空 BattleLogEntry 没有 godview 所读取的 turn 等属性，Python 返回 INTERNAL_ERROR。迁移保留该错误，且不缓存这个异常结果；不是为通过测试返回虚构战报。查询内容没有统一成一种“更合理”规则。

## 5. 排除与限制

本轮本地直接调用排除了 Hub/协议为未实现接口的原因；没有实验说明网络容量。并未测量或证明性能提升。1/2/4 设置共享串行实现，只验证配置不改变结果。

三 display 配置并非三个真实图形后端验收；没有像素、真实渲染或 VLM 截帧对照。三个 Unit 不能证明 5000/1000 的 30Hz。旧 R2e 负性能结果保持有效历史身份，不改写。
